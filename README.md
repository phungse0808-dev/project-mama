# ระบบเฝ้าระวังและพยากรณ์ผลกระทบสุขภาพจากฝุ่น PM2.5

โปรเจคจบ — ระบบสารสนเทศเฝ้าระวังคุณภาพอากาศ **ที่ใช้ข้อมูลจริงทั้งหมด**

## จุดเด่นสำคัญ

ข้อมูลในระบบนี้ **ไม่ใช่ข้อมูลจำลอง** แต่เป็นข้อมูลจริงที่ระบบดึงมาเองจากแหล่งเปิดสาธารณะ
ซึ่งเป็นจุดที่โปรเจคจบสายนี้ส่วนใหญ่ทำไม่ได้ เพราะข้อมูลสุขภาพติดข้อจำกัด PDPA

## แหล่งข้อมูล

| แหล่ง | ข้อมูล | ต้องใช้ API key | สถานะที่ทดสอบแล้ว |
| --- | --- | --- | --- |
| Air4Thai กรมควบคุมมลพิษ | PM2.5, PM10, O₃, CO, NO₂, SO₂ รายชั่วโมง 174 สถานี | ไม่ต้อง | ใช้งานได้ |
| NASA POWER | อุณหภูมิ ฝน ความชื้น ความเร็วลม ความกดอากาศ รายวัน | ไม่ต้อง | ใช้งานได้ |

**ข้อจำกัดที่พบ:** Air4Thai ให้เฉพาะข้อมูล ณ ชั่วโมงล่าสุด ไม่เปิด endpoint ข้อมูลย้อนหลัง
(ทดสอบแล้ว 4 endpoint ได้ 404 ทั้งหมด) ระบบนี้จึงออกแบบให้ **เก็บสะสมข้อมูลเองทุกชั่วโมง**
ซึ่งกลายเป็นส่วนหนึ่งของตัวระบบและเขียนเป็นวิธีดำเนินการในบทที่ 3 ได้

```
   │  ├─ db.py           การเชื่อมต่อฐานข้อมูล
   │  ├─ models.py       โครงสร้างตาราง 4 ตาราง
   │  ├─ air4thai.py     ดึงและแปลงข้อมูลคุณภาพอากาศ
   │  └─ weather.py      ดึงข้อมูลอากาศจาก NASA POWER
   ├─ scripts/
   │  ├─ collect_air.py      เก็บข้อมูลอากาศหนึ่งรอบ (ตัวจัดตารางงานเรียกทุกชั่วโมง)
   │  ├─ collect_weather.py  เก็บข้อมูลอากาศรายวัน
   │  ├─ show_status.py      ดูสถานะและความครบถ้วนของข้อมูล
   │  ├─ show_sample.py      ดูตัวอย่างข้อมูลจริง
   │  ├─ fix_provinces.py    แก้ชื่อจังหวัดย้อนหลังเมื่อปรับตรรกะการแยกชื่อ
   │  └─ run_collect.bat     ตัวเรียกงานสำหรับ Windows Task Scheduler
   └─ data/
      ├─ airquality.db   ฐานข้อมูล SQLite
      ├─ collector.log   บันทึกการทำงานของตัวเก็บข้อมูล
      └─ raw/            ไฟล์ JSON ดิบ แยกตามวัน
```

## ฐานข้อมูล

| ตาราง | หน้าที่ |
| --- | --- |
| `station` | สถานีตรวจวัด 174 แห่ง พิกัด จังหวัด |
| `reading` | ค่าตรวจวัดรายชั่วโมง มี unique key `(station_id, measured_at)` กันข้อมูลซ้ำ |
| `weatherdaily` | ข้อมูลอากาศรายวันรายจังหวัด |
| `collectionlog` | บันทึกการดึงข้อมูลทุกครั้ง ใช้รายงานความครบถ้วนของข้อมูลในบทที่ 4 |

ใช้ SQLite เพื่อความสะดวกในการพัฒนา ย้ายไป PostgreSQL ได้โดยแก้ `DATABASE_URL`
ใน `app/config.py` บรรทัดเดียว

## การเก็บข้อมูลอัตโนมัติ

ระบบตั้ง Windows Scheduled Task ชื่อ `AirQualityCollector` ให้รันทุกชั่วโมงที่นาทีที่ 5
(เว้น 5 นาทีหลังต้นชั่วโมงเพื่อให้ต้นทางอัปเดตข้อมูลเสร็จก่อน)

ตรวจสอบสถานะ

```bash
powershell "Get-ScheduledTaskInfo -TaskName AirQualityCollector"
```

ยกเลิกการเก็บอัตโนมัติ

```bash
powershell "Unregister-ScheduledTask -TaskName AirQualityCollector -Confirm:$false"
```

## ปัญหาทางเทคนิคที่แก้ไปแล้ว (เขียนลงเล่มได้)

1. **ใบรับรอง SSL ของ Air4Thai ไม่ครบ** — เซิร์ฟเวอร์ต้นทางไม่ได้ติดตั้ง intermediate certificate
   ทำให้ Python เชื่อมต่อไม่ได้ แก้โดยใช้ไลบรารี `truststore` ให้ Python ใช้ที่เก็บใบรับรอง
   ของระบบปฏิบัติการแทน **ไม่ใช้วิธีปิดการตรวจสอบ SSL** ซึ่งไม่ปลอดภัย

2. **รูปแบบที่อยู่ของสถานีไม่เป็นมาตรฐาน** — พบ 3 รูปแบบ ทั้งแบบมีคอมมา แบบมีคำนำหน้า `จ.`
   และสถานีของ กทม. ที่ไม่ระบุจังหวัดเลย ทำให้แยกชื่อจังหวัดได้ 95 ค่าทั้งที่ควรมีไม่เกิน 77
   แก้แล้วเหลือ 74 จังหวัดซึ่งถูกต้อง (มี 3 จังหวัดที่ไม่มีสถานีตรวจวัด)

3. **ค่า -1 ไม่ใช่ค่าที่วัดได้** — ต้นทางใช้ `-1` แทนกรณีไม่มีข้อมูล ถ้าเก็บตรงๆ
   โมเดลจะเข้าใจว่าค่าฝุ่นติดลบ ระบบจึงแปลงเป็นค่าว่างก่อนบันทึก

4. **การเข้ารหัสอักขระตอนรันผ่าน Task Scheduler** — Windows ใช้ codec `cp1252`
   ซึ่งเขียนภาษาไทยลง log ไม่ได้ ต้องกำหนด `PYTHONIOENCODING=utf-8`

## วิธีเปิดใช้งานระบบ

ระบบนี้เป็นเว็บแอปพลิเคชัน เปิดดูด้วยเบราว์เซอร์ปกติ

**ดับเบิลคลิกไฟล์ `start_web.bat`** ที่โฟลเดอร์หลักของโปรเจค
ระบบจะเปิดเซิร์ฟเวอร์แล้วเปิดเบราว์เซอร์ให้อัตโนมัติที่ http://127.0.0.1:8000

ปิดเซิร์ฟเวอร์ด้วย `stop_web.bat` หรือปล่อยไว้ก็ได้

| ไฟล์ | หน้าที่ |
| --- | --- |
| `start_web.bat` | เปิดเซิร์ฟเวอร์และเปิดเว็บ เรียก `scripts/start_web.ps1` |
| `stop_web.bat` | หยุดเซิร์ฟเวอร์ เรียก `scripts/stop_web.ps1` |

เบื้องหลังใช้เซิร์ฟเวอร์เพียงตัวเดียว โดย FastAPI เสิร์ฟทั้งหน้าเว็บที่ build แล้ว
และ REST API พร้อมกัน ทำให้ไม่ต้องเปิดสองหน้าต่างและไม่ติดปัญหา CORS

**การเก็บข้อมูลทุกชั่วโมงไม่เกี่ยวกับการเปิดเว็บ** ทำงานแยกผ่าน Windows Task Scheduler
ปิดเว็บไปข้อมูลก็ยังเก็บต่อตามปกติ

> **ข้อสำคัญ** ถ้าแก้โค้ดหน้าเว็บใน `frontend/src` ต้องสั่ง `npm run build` ใหม่
> ไม่เช่นนั้นเว็บจะยังแสดงเวอร์ชันเดิม เพราะเซิร์ฟเวอร์เสิร์ฟไฟล์ที่ build ไว้แล้ว
> ตอนพัฒนาให้ใช้ `npm run dev` ที่พอร์ต 5173 ซึ่งเห็นการแก้ไขทันที

## หน้าแดชบอร์ด

สร้างด้วย React + TypeScript (Vite) แผนที่ใช้ Leaflet กราฟใช้ Recharts

**สั่งรัน** (ต้องเปิดเซิร์ฟเวอร์ backend ไว้ด้วย)

```bash
cd frontend && npm install && npm run dev
```

เปิดที่ http://localhost:5173

ประกอบด้วย 5 ส่วน

1. **การ์ดสรุป** — PM2.5 เฉลี่ยทั้งประเทศ จำนวนสถานีที่รายงาน จุดที่ค่าฝุ่นสูงสุด
2. **แถบสัดส่วนระดับคุณภาพอากาศ** — ตามเกณฑ์ AQI 5 ระดับของประเทศไทย ไม่ใช่เกณฑ์ US EPA
3. **แผนที่สถานี** — หมุด 173 จุด สีตามระดับ ขนาดตามค่าฝุ่น คลิกดูรายละเอียดและกราฟได้
4. **อันดับจังหวัด** — เรียงตามค่าฝุ่นเฉลี่ยของสถานีในจังหวัดนั้น
5. **แผงคุณภาพข้อมูล** — ความครบถ้วนของข้อมูลและประวัติการเก็บ ใช้เขียนบทที่ 4

## ระบบระบุตัวตนและคำแนะนำเฉพาะบุคคล

เปิดโปรแกรมครั้งแรกจะให้กรอกชื่อ ระบบจำชื่อไว้ในเบราว์เซอร์ จึงไม่ต้องกรอกซ้ำทุกครั้ง
ผู้ใช้ตั้งจังหวัดและกลุ่มเสี่ยงของตัวเองได้ แล้วระบบแสดงคำแนะนำสุขภาพให้ตรงกับคนคนนั้น

มีกลุ่มเสี่ยง 7 กลุ่ม แต่ละกลุ่มมีคำแนะนำต่างกันใน 5 ระดับคุณภาพอากาศ รวม 35 ชุดคำแนะนำ
เพราะฝุ่นระดับเดียวกันส่งผลต่างกันมากในแต่ละกลุ่มคน เช่น ผู้ป่วยหอบหืดอาการกำเริบได้
ที่ระดับซึ่งคนทั่วไปยังไม่รู้สึกอะไร

### ข้อจำกัดด้านความปลอดภัยที่ต้องรู้

**ระบบนี้ไม่มีรหัสผ่าน จึงไม่ใช่ระบบยืนยันตัวตนเพื่อความปลอดภัย**
ใครก็พิมพ์ชื่อของคนอื่นแล้วเข้าใช้แทนได้

เลือกออกแบบแบบนี้เพราะข้อมูลคุณภาพอากาศเป็นข้อมูลสาธารณะ การระบุตัวตนมีไว้เพียง
เพื่อจำค่าที่ผู้ใช้ตั้งไว้ ไม่ได้ใช้ควบคุมสิทธิ์การเข้าถึงข้อมูล

**ห้ามนำไปใช้เก็บข้อมูลสุขภาพรายบุคคลหรือข้อมูลที่เป็นความลับ** ถ้าภายหลังต้องเก็บข้อมูล
ส่วนบุคคล ต้องเปลี่ยนไปใช้รหัสผ่านที่เข้ารหัสพร้อมระบบจัดการ session ที่ถูกต้อง

## แผงแจ้งเตือนและข้อมูลอากาศ

**แผงแจ้งเตือน** แสดงพื้นที่ที่ค่าฝุ่นเกินเกณฑ์ แยกเป็นสองระดับ

| เกณฑ์ | ค่า | เหตุผลที่ต้องแยก |
| --- | --- | --- |
| มาตรฐานประเทศไทย | 37.5 µg/m³ | เกณฑ์ที่ใช้ประกาศเตือนอย่างเป็นทางการ |
| ค่าแนะนำองค์การอนามัยโลก | 15 µg/m³ | เกณฑ์สากล เข้มกว่ามาตรฐานไทย 2.5 เท่า |

ถ้าแสดงแค่เกณฑ์ไทยอย่างเดียวจะทำให้เข้าใจว่าอากาศปลอดภัยทั้งที่ยังมีผลต่อสุขภาพระยะยาว
ตัวอย่างจากข้อมูลจริงวันที่ 18 สิงหาคม 2569 ซึ่งเป็นฤดูฝนที่อากาศดีที่สุดของปี
ไม่มีสถานีใดเกินมาตรฐานไทยเลย แต่มีถึง 50 สถานีที่เกินค่าแนะนำขององค์การอนามัยโลก

**แผงข้อมูลอากาศ** แสดงปริมาณฝน อุณหภูมิ และความเร็วลมย้อนหลัง เลือกได้ทั้ง 74 จังหวัด
และเลือกช่วงเวลาได้ตั้งแต่ 1 เดือนถึง 5 ปี เป็นการนำข้อมูล 178,932 แถวที่เก็บไว้มาใช้
และเป็นการปูทางไปสู่โมเดลพยากรณ์ เพราะตัวแปรเหล่านี้คือตัวแปรต้นของโมเดล

## สิ่งที่ยังไม่ได้ทำ

- โมเดลพยากรณ์ค่าฝุ่นล่วงหน้า 24–72 ชั่วโมง
- ระบบแจ้งเตือนกลุ่มเปราะบาง
- การประเมินผลกระทบต่อสุขภาพ
- นำระบบขึ้นออนไลน์ (ตอนนี้รันบนเครื่องเท่านั้น)
- การทำความสะอาดข้อมูล เช่น สถานีที่ส่งข้อมูลค้าง (พบ 1 สถานีที่ข้อมูลค้างตั้งแต่ 17 ก.ค. 2569)
- แก้เวลาในแถวเก่าที่บันทึกเป็น UTC ก่อนเปลี่ยนมาใช้เวลาไทย มีสคริปต์ `scripts/fix_timestamps.py`
  เตรียมไว้แล้วแต่ยังไม่ได้รัน ทำให้ตัวเลขความครบถ้วนตอนนี้ต่ำกว่าความจริง
